Synchro d'un dossier du coffre ↔ dossier Google Drive

Architecture technique tirée de la spec docs/superpowers/specs/2026-11-06-synchro-dossier-drive-design.md et du code actuel. Bidirectionnelle, par passes périodiques.

Vue d'ensemble

nouveauà créer · existantréutilisé tel quel ou étendu

Frontières

Front (thread principal)

  • Seul à détenir le jeton Google : toute la conversation avec Drive vit ici.
  • Liaisons par appareil en localStorage.
  • UI HeroUI via @supernote/ui, modal plein écran < 768px.

Worker / base

  • Ne parle jamais à Drive.
  • Table locale drive_sync_file (hors op-log, comme cal_*).
  • Écrit les notes via les routes à hooks, pour que le salon suive.

Services externes

  • Google Drive API v3, scope drive demandé à la 1ʳᵉ liaison.
  • Serveur sync Scalingo : aucun changement.

Flux d'une passe (par liaison)

« Changé » = entity.fileHash ≠ localHash côté coffre, md5Checksum ≠ driveMd5 côté Drive, comparés à la ligne drive_sync_file du dernier accord.
